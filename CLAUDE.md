# nookagame — CLAUDE.md

Обучающая игра про ИИ для детей. Статический сайт, деплой на GitHub Pages (nookagame.ru).
Push в `main` = сразу продакшн. Никаких прямых коммитов в `main` — только через PR.

## Стек и структура

- Чистый HTML/CSS/JS, без сборки, без фреймворков, без npm. Так и остаётся.
- `index.html` — главная. Каждая папка (`buy/`, `access/`, `games/`, `legal/`, …) — отдельная страница `index.html`.
- `games/*.html` — игры. Общий код — в `games/nooka-*.js` (core, ui, access, levels, bot, hero, crew, brain, gallery).
- `games/nooka-ui.css`, `fonts/nooka-fonts.css` — общие стили. Новые стили — туда, а не inline.
- `tools/` — служебные страницы (генератор кодов, лог). Не для пользователей.
- Файлы `_*.html` и `_*.js` — черновики, в git не попадают (.gitignore).

## Правила работы

1. Перед любой задачей крупнее правки одного файла — сначала план, потом код. Жди подтверждения.
2. Новый JS — в отдельный модуль `games/nooka-<name>.js`, не inline в HTML.
   В `games/ai.html` и `games/prompt.html` inline-скрипты только уменьшать, не увеличивать.
3. Не дублировать CSS между страницами. Если стиль нужен на двух страницах — в общий файл.
4. Каждое изменение — проверить в браузере: открыть страницу через `python3 -m http.server`, пройти сценарий руками.
5. Не ломать ссылки: после переименования/удаления страницы — `grep` по всему репо и обновить `sitemap.xml`.
6. Коммиты маленькие, сообщение на русском в стиле «Что сделано: зачем». Не смешивать рефакторинг и фичи в одном коммите.
7. Тексты для детей и родителей — простой человеческий язык, без жаргона. Не переписывать существующие тексты без запроса.

## Доступ и оплата

- Логика доступа — `games/nooka-access.js`. Сейчас проверка кодов на клиенте — это временно.
- Не добавлять новые обходные пути к платному контенту через localStorage/sessionStorage.
- Не трогать `tools/codes.html`, `legal/requisites.js` и тексты оферты без явного запроса.

## Запрещено

- Коммитить в `main` напрямую.
- Добавлять внешние зависимости, CDN-скрипты, трекеры без обсуждения.
